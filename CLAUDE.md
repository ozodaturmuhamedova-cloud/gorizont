## 1. Что мы строим

Это веб-приложение для продажи квартир в новостройке с подбором мебели. В нём две связанные сцены:

| Сцена | Назначение | Технология |
|-------|-----------|------------|
| **2D — Поэтажный план** | Выбор этажа и квартиры. Статусы (свободна / бронь / продана), фильтры по комнатности, площади и цене, карточка квартиры. | `react-konva` (Canvas 2D) |
| **3D — Тур по квартире** | Осмотр выбранной квартиры. Два режима камеры: Orbit (вид сверху/сбоку) и Walk (прогулка от первого лица на высоте глаз клиента, рассчитанной по его росту). Можно сменить отделку, расставить мебель из каталога и увидеть итоговую смету «квартира + мебель». | `three` + `@react-three/fiber` + `@react-three/drei` |

Пользовательский сценарий: открыть план, выбрать этаж, кликнуть по квартире, посмотреть карточку, нажать «Смотреть в 3D», нажать «Прогуляться», указать рост, пройтись по комнатам, обставить квартиру, получить смету и оставить заявку (заявка — заглушка).

**Главный архитектурный принцип: один источник данных.** Геометрия квартиры (полигоны комнат, стены, двери, окна) хранится один раз в JSON в метрах. 2D-сцена рисует её, а 3D-сцена экструдирует из неё стены. Дублировать геометрию запрещено.

## 2. Стек

- **Сборка:** Vite + React 18 + TypeScript (`strict: true`)
- **Состояние:** Zustand (один стор, разбит на слайсы)
- **2D:** `konva`, `react-konva`
- **3D:** `three`, `@react-three/fiber`, `@react-three/drei` (`OrbitControls`, `PointerLockControls`, `Environment`, `ContactShadows`, `useGLTF`)
- **UI:** Tailwind CSS. Компоненты пишем сами, без тяжёлых UI-китов.
- **Роутинг:** `react-router-dom`. Маршрут `/apartment/:id/3d` грузится лениво (`React.lazy`).
- **Тесты:** Vitest + Testing Library (unit), Playwright (e2e smoke)
- **Линт:** ESLint + Prettier

Новые зависимости добавляй только при реальной необходимости. Причину пиши в описании коммита.

## 5. Модель данных и система координат

```ts
type Vec2 = [number, number];          // метры

interface Apartment {
  id: string;                          // "s1-f5-a3" (секция-этаж-номер)
  floor: number;
  rooms: 0 | 1 | 2 | 3 | 4;            // 0 = студия
  area: number;                        // м², считается из полигонов и сверяется в тесте
  price: number;                       // ₽
  status: 'free' | 'reserved' | 'sold';
  outline: Vec2[];                     // контур квартиры на плане этажа
  roomsGeometry: Room[];
  walls: Wall[];
  openings: Opening[];                 // двери и окна, привязаны к стене
}
interface Room   { id: string; type: 'living'|'bedroom'|'kitchen'|'bath'|'hall'|'balcony'; polygon: Vec2[] }
interface Wall   { a: Vec2; b: Vec2; thickness: number; height: number }  // height по умолчанию 2.7
interface Opening{ wallIndex: number; offset: number; width: number; kind: 'door'|'window'; sill?: number; height: number }
interface FurnitureItem {
  id: string; name: string; price: number;
  size: [w: number, d: number, h: number];          // ширина, глубина, высота, м
  model?: string; color?: string;
  allowedRooms?: Room['type'][];
  // --- правила расстановки (см. §7.2) ---
  category: 'bed' | 'sofa' | 'table' | 'chair' | 'storage' | 'tv' | 'kitchen' | 'plumbing' | 'decor';
  placement: 'wall' | 'corner' | 'center';          // спиной к стене / в угол / свободно
  clearance: { front: number; sides: number; back: number }; // свободная зона, м
  priority: number;                                 // 0–100, больше — ставится раньше
  group?: string;                                   // 'dining' — стол + стулья как одно целое
  pairWith?: { itemId: string; distance: [min: number, max: number]; facing: true };
  blocksWindow?: boolean;                           // true, если h > подоконника
  compactAlt?: string;                              // id компактной замены, если не влез
}
interface PlacedFurniture { itemId: string; position: Vec2; rotation: number /* рад */ }
```

**Хранение в `building.json`.** Геометрия лежит в `layouts[]` (`id`, `rooms`, `area`, `outline`, `roomsGeometry`, `walls`, `openings`) один раз на планировку. Квартиры в `apartments[]` хранят только `id`, `number`, `floor`, `layoutId`, `price`, `status`; `parseBuilding` собирает из них полный `Apartment`. Входная дверь помечена `entry: true` (ровно одна на планировку). Координаты — в системе этажа, в метрах.

**Координаты (важно, не путать):**
- 2D: `x` вправо, `y` вниз, единица — метр. Перевод в пиксели делает только `scene2d` через `scale` у Stage.
- 3D: `x` = 2D `x`, `z` = 2D `y`, `y` — вверх. Функция `to3D([x, y], h) => [x, h, y]` находится в `domain/geometry.ts`.
- Пол квартиры лежит на `y = 0`. Квартира центрируется в начале координат через `centerOf(outline)`.

## 6. Правила для 2D-сцены

- Используй три слоя Konva: `background` (контур этажа, лестницы, лифты; статичный, `listening={false}`), `apartments` (интерактив), `overlay` (подписи, hover).
- Цвета статусов: free — `#22c55e`, reserved — `#f59e0b`, sold — `#9ca3af`. Проданные квартиры не кликаются, но показывают тултип.
- Hover подсвечивает квартиру, клик выбирает её и открывает `ApartmentCard`.
- Квартиры, не прошедшие фильтр, получают прозрачность 0.25 и не скрываются, чтобы план оставался читаемым.
- Zoom колесом мыши к курсору, pan перетаскиванием. Масштаб ограничен диапазоном 0.5–4.
- Stage адаптивен: подстраивается под контейнер через `ResizeObserver`. Мобильные: pinch-zoom.
- Внутри выбранной квартиры показываются комнаты с подписями «Кухня 12.4 м²». Площадь считается через `polygonArea`.
- **Подписи — только через `PlanLabel`**: позиция в метрах, размер шрифта в пикселях (`labelPx`, с границами min/max). Шрифт в долях метра на масштабированной сцене браузер рисует с разъехавшимися буквами.
- Математика вида (вписывание, zoom к точке, pinch, видимая область) — в `domain/planView.ts`, с тестами.
- Для e2e в dev-сборке есть `window.__gorizontPlan.apartmentPoint(id)`; в прод его нет.
- CI публикует скриншоты из `tests/e2e/screens.spec.ts` в ветку `ci-screens` — для визуальной проверки без скачивания артефактов.

## 7. Правила для 3D-сцены

- `<Canvas shadows dpr={[1, 2]} camera={{ fov: 50 }}>` и `frameloop="demand"` в режиме Orbit (рендер по событию), `"always"` в режиме Walk.
- Стены строятся из `Wall` + `Opening`. Используй `Shape` с `holes` → `ExtrudeGeometry`, либо сегменты-боксы вокруг проёмов. Выбери один способ и держись его. Окна — полупрозрачное стекло (`MeshPhysicalMaterial`, `transmission`).
- Пол строится по полигонам комнат (`ShapeGeometry`). Материал зависит от типа комнаты и выбранной отделки.
- Потолок в Orbit скрыт, в Walk виден.
- Освещение: `Environment` из `Lightformer` (без загрузки HDR из сети), один `directionalLight` с тенями, `ContactShadows` под мебелью. Тональная компрессия — `NeutralToneMapping` (ставится в `onCreated`), иначе светлая отделка выглядит серой.
- Геометрия сцены (сегменты стен, рамы, подоконники, наличники, пол, домашний вид камеры) считается в `domain/scene3d.ts` и покрыта тестами; компоненты `scene3d/` только рисуют.
- В dev-сборке есть `window.__gorizont3d` (`calls()`, `triangles()`, `frames()`) — e2e проверяет бюджет draw calls.
- **Мебель:** если в `furniture.json` указан `model`, загружай `.glb` через `useGLTF` (с `Suspense` и фолбэком). Если модели нет, рисуй процедурный бокс по `size` нужного цвета. Приложение обязано работать вообще без .glb-файлов.
- **Расстановка:** при клике по полу (raycast) предмет ставится в точку клика. Перетаскивание по плоскости пола, поворот клавишами `Q/E` (шаг 15°) или ручкой гизмо, привязка к сетке 0.1 м. Вся логика проверок и автоматической расстановки описана в §7.2. 3D-слой только отображает статус и не считает его сам.
- Режим Walk описан отдельно в §7.1.

### 7.1. Режим прогулки (Walk) с учётом роста клиента

Клиент «заходит» в квартиру и видит её со своей высоты. Так он может оценить высоту потолков, подоконников и кухонных шкафов, а также проверить, удобно ли ему проходить между предметами мебели.

**Ввод роста (обязателен перед первым входом):**
- По кнопке «Прогуляться» открывается модальное окно `HeightDialog`. В нём поле «Ваш рост, см» (числовой ввод + слайдер) и кнопки «Начать» и «Отмена».
- Допустимый диапазон 100–220 см, шаг 1 см, по умолчанию 170. Вне диапазона кнопка «Начать» неактивна и показывается подсказка.
- Рост сохраняется в сторе (`persist` в `localStorage`), при следующих входах окно не показывается. Изменить рост можно кнопкой «Изменить рост» в HUD прямо во время прогулки, без выхода из режима.
- Без указанного роста в режим Walk войти нельзя. Это правило проверяется в `CameraRig`, а не только в UI.

**Расчёт (в `domain/walk.ts`, чистые функции с тестами):**
```ts
eyeHeight(heightCm)     = round2(heightCm / 100 * EYE_RATIO)   // EYE_RATIO = 0.936
collisionRadius(heightCm) = clamp(heightCm / 100 * 0.13, 0.18, 0.28)  // «плечи», м
walkSpeed(heightCm)     = clamp(heightCm / 100 * 0.8, 1.0, 1.6)       // м/с
```
Высота камеры = `eyeHeight`. Если `eyeHeight` ≥ высоты потолка − 0.1 м, камера опускается до этого предела и показывается предупреждение «Потолок ниже уровня ваших глаз». Все коэффициенты лежат в `domain/constants.ts`.

**Управление:**
- Десктоп: `PointerLockControls` (мышь — обзор), WASD/стрелки — движение, Shift — ускорение ×1.5, Esc — выйти из pointer lock (показывается пауза-оверлей «Кликните, чтобы продолжить»).
- Мобильные: виртуальный джойстик слева (движение), свайп по правой половине экрана (обзор). Pointer lock не используется.
- Скорость не зависит от FPS (умножать на `delta` из `useFrame`).

**Коллизии и навигация (считаются в 2D, в плоскости пола):**
- Клиент — круг радиуса `collisionRadius` в точке `(x, z)`.
- Стены непроходимы, кроме дверных проёмов: проход возможен, если ширина двери ≥ 2 × радиус. Окна непроходимы.
- Мебель непроходима (по её OBB). Нельзя выйти за `outline` квартиры, балкон доступен через балконную дверь.
- При упоре в препятствие движение скользит вдоль него (проекция вектора скорости на касательную), а не останавливается полностью.
- Если при смене роста или расстановке мебели клиент оказался внутри препятствия, он переносится в ближайшую свободную точку.

**Точка входа и HUD:**
- Старт: в прихожей (`room.type === 'hall'`) у входной двери, взгляд внутрь квартиры. Если прихожей нет, старт в центре самой большой комнаты.
- HUD: текущая комната и её площадь, рост клиента, кнопки «Изменить рост», «Выйти из прогулки», мини-план в углу с точкой и направлением взгляда (переиспользует данные 2D-плана).
- При выходе из Walk камера Orbit плавно возвращается к виду 3/4.
- Включён потолок, `frameloop="always"`. Расстановка мебели в Walk отключена, в Orbit — снова доступна.

**Реализация.** Препятствия — `walkObstacles(apt, placed, catalog)`: куски стен без проёмов межкомнатных дверей (окна и входная дверь — сплошные, из квартиры не выйти) и следы мебели. Шаг — `moveCircle`: подшаги не длиннее половины радиуса, после каждого выталкивание из препятствий, отсюда скольжение. Ввод с телефона идёт через `scene3d/walkInput.ts` (обычный объект, не стор). Pointer lock включается кликом по оверлею `#walk-resume`; клавиши работают и без захвата мыши. Для e2e в dev-сборке есть `window.__gorizontWalk.pose()` — позиция на плане, направление взгляда и высота камеры.

**Связь с мебелью.** autoLayout оставляет проход между дверями каждой комнаты для роста 195 см (`blockedDoors`), поэтому прогулка с «Готовым комплектом» доходит до каждой комнаты (инвариант `walkViolations` в `testing/random/invariants.ts`).

### 7.2. Расстановка мебели

Вся логика находится в `src/domain/layout/` и состоит из чистых функций без React и three. Она работает в 2D (плоскость пола) с повёрнутыми прямоугольниками (OBB). Одни и те же функции используются в трёх местах: кнопка «Готовый комплект», ручная расстановка и генератор `furnitureGen.ts` для тестов.

**Основная идея.** Каждый расставленный предмет состоит из двух прямоугольников:
- `footprint` — сам предмет (`size[0] × size[1]`, повёрнут на `rotation`);
- `clearanceBox` — footprint, расширенный на `clearance.front/sides/back` с учётом ориентации («перед» — сторона, противоположная спинке).

Правила пересечения:

| Пара | Можно? |
|---|---|
| footprint × footprint | ❌ никогда |
| footprint × чужой clearanceBox | ❌ (иначе шкаф не откроется, к кровати не подойти) |
| clearanceBox × clearanceBox | ✅ (общий проход) |
| footprint × стена или контур комнаты | ❌ |
| clearanceBox × стена | ✅ только со стороны `back` (спинка у стены), с остальных сторон ❌ |
| footprint или clearanceBox × зона открывания двери | ❌ |
| footprint с `blocksWindow` × зона окна | ❌ |
| предмет между двумя комнатами | ❌ — предмет целиком в одной комнате |

**Нормы свободных зон (значения по умолчанию в `domain/constants.ts`, переопределяются в `furniture.json`):**

| Где | Минимум, м |
|---|---|
| Основной проход по комнате | 0.8 (`MAIN_PASSAGE`) |
| Второстепенный проход | 0.6 (`SECONDARY_PASSAGE`) |
| Перед шкафом с распашными дверями | 0.9 |
| Сбоку от двуспальной кровати | 0.6 (в узкой комнате — с одной стороны) |
| Перед кухонным гарнитуром | 1.0 |
| За стулом у обеденного стола | 0.75 |
| Перед унитазом / раковиной | 0.6 |
| Перед дверью | квадрат «ширина двери × ширина двери» со стороны открывания |
| Перед окном (для `blocksWindow`) | 0.5 вглубь комнаты по всей ширине окна |

**Подготовка комнаты (`zones.ts`).** Функция `freeArea(room, apartment)` возвращает полигон комнаты, внутреннюю линию стен (с учётом толщины), список запретных зон (двери), список зон окон и сегменты стен без проёмов (только к ним можно прислонять `wall`-предметы).

**Кандидаты (`candidates.ts`).** Для `wall` позиции берутся вдоль каждого глухого сегмента стены с шагом 0.1 м, спинка к стене, отступ от стены 0.02 м. Для `corner` — каждый внутренний угол (≈ 90°) в двух ориентациях. Для `center` — сетка 0.2 м внутри свободной зоны с поворотами 0°/90° (и 45° только для `decor`). Кандидаты, которые заранее не влезают по габаритам, отсекаются сразу.

**Оценка (`score.ts`).** Сумма весов, каждый вес — именованная константа:
- `bed`: изголовье у стены (+30), не напротив двери (+10), подход с двух сторон (+15), с одной (+5), не под окном (+5)
- `sofa`: спинкой к стене (+20), есть место для `pairWith` (ТВ) напротив на нужной дистанции (+25), лицом к окну или ТВ (+10)
- `tv`: напротив дивана из пары (+30), не на фоне окна (+10)
- `table` (`dining`): ближе к кухне (+15), у окна (+10), стулья со всех доступных сторон (+5 за каждый)
- `storage`: у глухой стены (+15), рядом с дверью комнаты (+10), не перекрывает окно (обязательно)
- `kitchen`: вдоль стены, ближайшей к стояку/окну (+20), сплошной линией или углом (+15)
- общее: перекрывает окно ниже подоконника (−20), ближе 0.3 м к двери (−15), оставляет проход < `MAIN_PASSAGE` до другой двери (−30)
- случайная добавка `rng.float(0, JITTER)` с `JITTER = 3`, чтобы при разных seed получались разные, но разумные варианты

**Группы.** Предметы с одинаковым `group` (стол + стулья, кровать + тумбочки) сначала собираются в составной объект с общим footprint и clearance, ставятся как один предмет, а затем раскладываются обратно. Стулья, которые не влезли, убираются по одному, пока группа не встанет; минимум 2 стула.

**Пары (`pairWith`).** После установки первого предмета пары второй ищется только в коридоре дистанций `[min, max]` строго напротив. Если места нет, оценка первого предмета снижается и кандидат пересматривается.

**Алгоритм `autoLayout(room, items, rng, opts)`:**
1. Подготовить `freeArea`.
2. Отсортировать: `priority` по убыванию, затем площадь footprint по убыванию.
3. Для каждого предмета: сгенерировать кандидатов → отфильтровать через `fits()` → оценить → взять лучшего.
4. Если кандидатов нет: откатить предыдущий предмет и взять его следующего кандидата (глубина отката ≤ 3, всего ≤ 200 попыток на комнату).
5. Если не помогло: заменить на `compactAlt`; если и его нет — пропустить и записать в `skipped` с причиной.
6. Финальная проверка `isWalkable`: на сетке 0.1 м с радиусом `collisionRadius(170)` из `walk.ts` от двери комнаты должна быть достижима clearance-зона каждого предмета. Если нет — откат последнего предмета и повтор.
7. Вернуть `{ placed, skipped, score }`. Бюджет — < 30 мс на комнату, < 150 мс на квартиру.

**Ручная расстановка (`validate.ts`).** `validatePlacement(item, pose, room, placed)` возвращает `{ status: 'ok' | 'warning' | 'error', reasons: string[] }`:
- `error` (красный, поставить нельзя): footprint пересекает стену, другую мебель, дверной проём или выходит из комнаты;
- `warning` (жёлтый, поставить можно с подсказкой): перекрыт clearance — «Шкаф не откроется полностью», «Проход 0.5 м — узковато», «Перекрыто окно»;
- `ok` (зелёный).

Тексты причин лежат в `strings.ts`.

Поведение при перетаскивании:
- **Притяжение к стене.** Если у `wall`-предмета спинка ближе `SNAP_DISTANCE = 0.15` м к глухой стене, предмет поворачивается и прижимается к ней.
- **Притяжение в угол.** Для `corner` то же самое в радиусе 0.25 м от угла.
- **Подсветка зон.** Footprint показывается цветом статуса, clearanceBox — полупрозрачным прямоугольником на полу. Подсказка из `reasons[0]` висит рядом с курсором.
- **Производительность.** Валидация во время перетаскивания идёт не чаще одного раза за кадр и сравнивает предмет только с мебелью его комнаты (до ~15 предметов) — отдельный broad-phase не нужен. Если комнаты станут больше, добавь сетку или AABB-отсев.

**Кнопка «Готовый комплект».** Вызывает `autoLayout` для каждой комнаты с базовым набором по типу комнаты (`presets` в `furniture.json`; в студии гостиная получает и кухонный набор). Пропущенные предметы показываются в смете отдельным списком «Не поместилось» с причиной. Каждое нажатие — новый seed (1, 2, 3…), то есть другой, но воспроизводимый вариант.
- Производительность: одинаковые предметы рендерятся одной `InstancedMesh` с геометрией из слитых деталей и цветами в вершинах (`scene3d/furnitureGeometry.ts`, кеш на предмет). При уходе со страницы геометрия освобождается. Цель — ≥ 50 FPS на встроенной графике ноутбука и < 150 draw calls.

**Ступени строгости в autoLayout (`fits(shape, zones, others, level)`).** Сначала `'strict'` (вся таблица); если предмет никуда не встаёт — `'door'` (зона подхода может заходить в зону открывания двери); затем `'tight'` (зоны подхода соседей могут перекрываться). За каждое послабление — штраф в оценке. Жёсткие правила (стены, пересечения, двери, высокие предметы у окна) не ослабляются никогда, а доступ к каждому предмету всё равно проверяет `isWalkable`. Ручная расстановка показывает такие случаи жёлтым (warning).

**Особые зоны подхода.** У стула зона сзади — место, чтобы его отодвинуть, поэтому она не может упираться в стену. У кровати боковые зоны могут упираться в стену (узкая спальня, подход с одной стороны). Стол группы `dining` ставится, только если вокруг встанут хотя бы два стула (`MIN_CHAIRS`).

**Для e2e** в dev-сборке есть `window.__gorizontFurnish.roomPoint(typeOrId)` — экранная точка центра комнаты, по ней тест кликает по полу.

## 8. Состояние

- `selectionSlice`: `floor`, `apartmentId`
- `filtersSlice`: `rooms[]`, `areaRange`, `priceRange`, `onlyFree`

## 9. Стиль кода

- TypeScript strict, без `any`. Всё внешнее (JSON) валидируй на входе, допустимы Zod или ручной type-guard.
- Компоненты — функциональные, файлы `PascalCase.tsx`. Утилиты пиши в `camelCase.ts`.

- Интерфейс на русском. Все строки собраны в `src/ui/strings.ts`.

### 10.1. Случайные комнаты и мебель для тестов

Ручных данных из `building.json` мало, чтобы поймать ошибки геометрии, коллизий и прогулки. Поэтому в проекте есть генератор случайных, но **воспроизводимых** квартир и наборов мебели. Генератор лежит в `src/testing/random/` и не попадает в прод-бандл: импортировать его можно только из тестов и `DevRandomPage`.

**Детерминизм:**
- Вся случайность идёт через `createRng(seed)` из `domain/rng.ts` (mulberry32; `testing/random/rng.ts` его реэкспортирует). Методы: `next()`, `int(a, b)`, `float(a, b)`, `pick(arr)`, `shuffle(arr)`, `chance(p)`.
- `Math.random()` в генераторе и тестах запрещён.
- Один и тот же `seed` всегда даёт ту же квартиру и ту же расстановку. Если тест падает, в сообщении обязательно выводится seed: `seed=1873: мебель пересекает стену`.

**Генератор комнат `randomApartment(seed, opts)`:**
- Опции: `rooms` (0–4 или `'any'`), `areaRange` (по умолчанию 25–120 м², пересекается с типичной площадью для комнатности), `ceiling` (2.5–3.2 м), `shape`: `'rect' | 'L' | 'any'`, `balcony`: `true | false | 'random'`.
- Алгоритм: строится внешний контур (прямоугольник или L-образная форма), затем он рекурсивно делится разрезами (BSP) на комнаты. Каждое помещение получает целевую площадь (прихожая 4–8 м², санузел 3,5–6, кухня 7–13, гостиная 15–24, спальня 9–15), разрез идёт пропорционально сумме площадей по обе стороны, по сетке 0.1 м. Минимальная сторона помещения 1.5 м, пропорции не уже 1:3. Внутри генератор считает в целых дециметрах.
- Коридор — верхняя сторона контура (`y = 0`): там входная дверь, окон нет. Прихожая — самое маленькое помещение у коридора; жилые комнаты и кухня — у фасада; проходить можно только через прихожую, гостиную и кухню (санузел и спальни не проходные).
- Квартиры с площадями помещений вне `AREA_LIMITS` (например, прихожая > 14 м²) отбрасываются и строятся заново; невыполнимые опции дают ошибку с seed.
- Обязательные помещения: прихожая, санузел, кухня (или кухня-ниша в студии). Жилых комнат столько, сколько указано в `rooms`. Балкон добавляется с вероятностью 0.4.
- Стены строятся по границам комнат: наружные толщиной 0.25 м, внутренние — 0.1 м.
- Двери ставятся так, чтобы из прихожей можно было дойти до любой комнаты (остовное дерево графа смежности комнат). Ширина двери 0.7–0.9 м, входная дверь — 0.9 м. Окна ставятся только на наружные стены жилых комнат и кухни: ширина 0.9–1.8 м, подоконник 0.8–0.9 м.
- Статус, цена и этаж тоже случайные, в правдоподобных диапазонах.
- Результат имеет тот же тип `Apartment`, что и данные из `building.json`, и проходит ту же валидацию.

**Генератор мебели `randomFurnished(seed, opts)`:**
- Берёт квартиру (переданную или сгенерированную по тому же seed) и каталог `furniture.json`.
- Для каждой комнаты выбирает случайный набор из подходящих по `allowedRooms`: спальня — кровать и, возможно, шкаф с тумбой; кухня — гарнитур, стол, стулья и т. д. Опция `density`: `'sparse' | 'normal' | 'dense'`.
- Расстановка делается через `autoLayout` из `domain/layout/` (§7.2) с тем же `rng`. Собственного алгоритма размещения в генераторе нет.
- Мебель использует свой поток случайных чисел (`seed ^ соль`), поэтому `randomFurnished(seed).apartment` совпадает с `randomApartment(seed)`.
- Опция `allowInvalid: true` специально генерирует ошибки (пересечения со стенами и другой мебелью) для негативных тестов коллизий.

**Инварианты (`invariants.ts`), проверяются для каждой сгенерированной квартиры:**
- Комнаты не пересекаются, их суммарная площадь равна площади контура (±0.1 м²), `area` совпадает с полигонами.
- Каждый проём лежит в пределах своей стены и не заходит на угол.
- Все комнаты достижимы из прихожей через двери (BFS по графу).
- Мебель находится внутри своей комнаты, не пересекает стены и другую мебель и не перекрывает двери (кроме режима `allowInvalid`).
- В режиме прогулки из точки старта можно дойти до центра каждой комнаты для роста 150 и 195 см. Проверка делается поиском пути по сетке 0.1 м с учётом `collisionRadius`.

**Где используется:**
- Unit/property-тесты: цикл по фиксированному списку seed'ов (по умолчанию 1…200; для `npm run test:fuzz` — 1…5000). Отдельная зависимость вроде fast-check не нужна.
- Тесты геометрии, коллизий, сметы и прогулки (`walk.test.ts`) прогоняются и на реальных данных, и на случайных.
- Снапшот-тест: для seed 1, 2, 3 сериализованная квартира совпадает со снапшотом. Он ловит случайные изменения генератора.
- E2E: Playwright открывает `/dev/random?seed=42&rooms=2&density=normal` и проходит сценарии 3D, мебели и прогулки на известной квартире.
- Ручная проверка: страница `DevRandomPage` (маршрут `/dev/random`, только `import.meta.env.DEV`). На ней поля seed, rooms, shape и density, кнопка «Случайная квартира» (новый seed), 2D-план и 3D-сцена рядом, а также подсветка нарушенных инвариантов. Seed всегда виден и отражается в URL.

Если тест падает на каком-то seed, этот seed добавляется в `REGRESSION_SEEDS` в `src/testing/random/seeds.ts` с комментарием, что именно ломалось.

## 11. Чего НЕ делать

- Не дублировать геометрию между 2D и 3D.
- Не тянуть реальные бренды, логотипы или чужие фото. Названия ЖК, мебели и цены вымышленные.
- Не подключать бэкенд. Оплата и заявка остаются заглушками (форма показывает «Заявка отправлена»).
- Не коммитить модели > 2 МБ и текстуры > 1024 px.
- Не импортировать `src/testing/**` из прод-кода и не использовать `Math.random()` в генераторах и тестах.
- Не ломать работу без WebGL: при отсутствии WebGL показывай 2D-план квартиры и сообщение.
