## Фаза 1а. Генератор случайных квартир и мебели (~1.5 дня)
Подробности — в CLAUDE.md §10.1. Делается сразу после домена, чтобы все следующие фазы тестировались на случайных данных.
- [x] `rng.ts`: mulberry32 + `int`, `float`, `pick`, `shuffle`, `chance`; тест детерминизма
- [x] `roomsGen.ts`: контур (прямоугольник или L-образный), BSP-разрезы по сетке 0.1 м, обязательные помещения, стены, двери (остовное дерево), окна на наружных стенах
- [x] `furnitureGen.ts`: подбор предметов по `allowedRooms` и `density`, режим `allowInvalid`. В этой фазе используется временный простой размещатель, в фазе 5 он заменяется на `autoLayout` (§7.2).
- [x] `invariants.ts`: непересечение комнат, сумма площадей, проёмы на стенах, достижимость комнат, мебель без коллизий (+ санузел не проходной, окно в каждой жилой комнате и кухне, правдоподобные площади)
- [x] Property-тесты на seed 1…200, скрипт `test:fuzz` на 1…5000, снапшоты для seed 1–3, файл `seeds.ts` с `REGRESSION_SEEDS`
- [x] Защита от попадания в прод: ESLint-правило `no-restricted-imports` для `src/testing/**` вне тестов и dev-страницы (+ запрет `Math.random` в домене, генераторах и тестах)

**Готово, когда:** 200 случайных квартир проходят все инварианты, генерация одной квартиры с мебелью занимает < 20 мс.

> Результат: 200 и 5000 квартир проходят все инварианты; квартира с мебелью генерируется за ~2 мс. Первый же fuzz-прогон нашёл seed 1433 и 2337 (граница 14 м² и погрешность float) — они в `REGRESSION_SEEDS`.
>
> Изменения плана:
> - `createRng` лежит в `domain/rng.ts`, а `testing/random/rng.ts` его реэкспортирует: тот же ГПСЧ нужен прод-коду для случайной добавки в `autoLayout` (§7.2), а домену нельзя импортировать из `testing/`.
> - BSP режет не случайно, а пропорционально целевым площадям помещений (прихожая 4–8 м², санузел 3,5–6 м², гостиная 15–24 м² …): при равных разрезах санузел и прихожая получались размером с комнату. Квартиры с площадями вне `AREA_LIMITS` перегенерируются.
> - Минимальная сторона любого помещения — 1.5 м (включая санузел).
> - Полные снапшоты seed 1–3 (`toMatchSnapshot`) Vitest запишет при первом локальном запуске — их нужно закоммитить. Дополнительно в тесте зашиты «отпечатки» seed 1–3 (площадь, типы комнат, число стен и проёмов, цена).
> - Инвариант «из точки старта достижима каждая комната для роста 150 и 195 см» остаётся в фазе 5а: ему нужен `walk.ts`.

## Риски и решения
| Риск | Решение |
|------|---------|
| Нет подходящих 3D-моделей мебели | Процедурные боксы с цветом — это рабочий вариант по умолчанию, модели необязательны |
| Сложная экструзия стен с проёмами | Сегменты-боксы вокруг проёма вместо `Shape.holes`, если появятся артефакты |
| Рассинхрон 2D и 3D | Единый JSON, `to3D` в домене и тест на совпадение габаритов |
| Слабые устройства | `dpr={[1, 2]}`, `frameloop="demand"`, отключение теней на мобильных |
| Генератор выдаёт «странные» планировки (узкие коридоры, проходные санузлы) | Ограничения на пропорции комнат (стороны не уже 1:3), санузел только с дверью в прихожую/коридор, такие seed'ы — в регрессию |
| Автоматическая расстановка выглядит «неестественно» | Веса в `score.ts` — именованные константы; подбирать на `/dev/random`, удачные и неудачные seed'ы фиксировать снапшотами |
| Перебор с откатом слишком медленный | Ограничения глубины и числа попыток, broad-phase, кандидаты отсекаются по габаритам до проверки |
| Укачивание в режиме прогулки | Умеренная скорость, без покачивания камеры, FOV 60–70°, плавные переходы вместо телепортов |
| Pointer lock недоступен (iframe, Safari) | Фолбэк: обзор перетаскиванием мыши с зажатой кнопкой |
